Automated Customer Feedback Analysis

Raw customer feedback in, structured real-time insight out. Nothing slips through, and unhappy customers get caught the same day.

Prepared by Jason Teixeira · Customer Success Manager (project scenario)

02 The problem

Feedback is only useful if you actually read it — fast

As the Customer Success Manager for a small online store, feedback comes in through a form and just... sits in a spreadsheet. Reading every response by hand doesn't scale, and the responses that matter most (the angry ones) are exactly the ones you can't afford to miss for three days.

SlowManual reading means insights arrive late, if at all.
InconsistentDifferent people "score" the same message differently.
RiskyOne overlooked complaint can turn into a public blow-up.

So I built a workflow that reads, classifies, and files every response automatically, and pings me the moment something goes negative.

03 What I built

One form in, structured insight out — no manual steps

A customer fills out a short form. Behind the scenes, the message is sent to an AI model that returns a clean sentiment label and a one-line summary, which lands in a spreadsheet automatically. If it's negative, I get an email.

CollectGoogle Form → a satisfaction rating + free-text feedback.
AnalyzeGemini classifies sentiment and writes a 1-sentence summary.
StoreParsed results drop into Google Sheets with a timestamp.
AlertNegative feedback triggers an instant email to me.

05 The AI part — and the catch

Getting clean JSON was the real work

The starter prompt returned the right idea, but it kept wrapping the answer in a Markdown code block (```json … ```) and occasionally added a friendly sentence before it. The JSON parser choked on both. Fixing that was the actual engineering here. I had to constrain the output hard:

// final prompt used in the Gemini module
You are a customer-feedback analyst. Analyze the feedback below and return
ONLY one JSON object. No Markdown, no code fences, no text before or after it.

Use exactly these two keys:
  "sentiment": one of "Positive", "Neutral", or "Negative"
  "summary" : a 1-sentence, third-person recap of the feedback

If the feedback is empty, return:
  {"sentiment":"Neutral","summary":"No feedback text was provided."}

Feedback: {{1.feedback_text}}

I also set the model temperature to 0.2 so classifications stay consistent across similar messages, and (where the module allows it) set the response type to JSON. After that, the parser read every response cleanly.

07 The insight

What the data told me

Across 7 test submissions:

Positive3
Neutral2

The useful part wasn't the split. It was the pattern in the negatives: both unhappy customers were describing the same class of problem, billing and account reliability (a double-charge with no reply, and repeated forced logouts). That's something a team can actually go fix, instead of a vague "some customers are unhappy."

08 Optional · shipped it anyway

Real-time alerts for negative feedback

I added a filter after the parse step: if sentiment = "Negative", Make sends an email straight to my inbox with the summary and a link to the sheet. That turns a passive log into an early-warning system, which is the whole point: catch the upset customer while there's still time to fix it.

Filter:  sentiment  Equal to  Negative
Subject: ⚠️ Negative feedback just came in
Body:    {{summary}}

09 Honest reflection

What I'd improve with more time & tools

  • Post to Slack, not just email — route negatives into a #customer-alerts channel so the whole team sees them, with a "claim" reaction to track who's handling it.
  • Add a topic tag — extend the prompt to also return a category (billing / shipping / bug / praise) so the sheet can be filtered and trended, not just read.
  • Fallback logic — if Gemini ever returns malformed JSON, catch it and write "needs review" instead of letting the scenario error out.
  • A live dashboard — a simple Looker Studio chart on top of the sheet showing sentiment over time, so trends are visible at a glance.
  • Confidence + urgency — ask the model to flag "very unsatisfied + negative" as high-priority so the loudest alarms rise to the top.
